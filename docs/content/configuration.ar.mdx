يختار المستودع محوّلات فلو في `flow.config.json` في جذره. يُفحص الملف على المخطط المشحون
(`schema/flow.config.schema.json`، الذي تقرؤه المحرّرات عبر `"$schema"`)، ومفتاحٌ مجهول أو نوعٌ خاطئ يوقف كل أمر،
مسمًّى بمساره. لا شيء يتخلّف إلى اختيار مؤسسة ما: الأمر الذي يحتاج إعدادًا لم تضبطه يرفض ويسمّيه. يُقرأ
`flow.config.json` وحده؛ ولا يقوم ملف آخر مقامه.

```json
{
  "$schema": "./node_modules/fflow/schema/flow.config.schema.json",
  "version": 1,
  "credentials": { "kind": "gh-user" },
  "secrets": { "kind": "env" },
  "gate": { "check": "pnpm verify" }
}
```

المرجع الكامل، مفتاحًا مفتاحًا بكل مفاتيحه الفرعية، هو
[قسم الإعداد في README](https://github.com/figentra/flow/blob/main/packages/flow/README.md#configuration).

## من أنت

| المفتاح       | يختار                                                                                                                                                                                  |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `credentials` | كيف تستوثق نداءات GitHub وgit عبر الشبكة: `env` (يضبط المستدعي `GH_TOKEN`)، أو `gh-user` (تسجيل دخولك في `gh`، عن قصد)، أو `wrapper` (أوامرك أنت). لا تراجعَ أبدًا إلى تسجيل دخول شخصي |
| `secrets`     | من أين تأتي الأسرار: `env` (يملأ المستدعي البيئة)، أو `sops` مع `oidc` ليفكّ سير عمل الموافقة تشفير مفتاح تطبيق البوابة بنفسه. لا يجلب فلو قيمةً ولا يطبعها                            |
| `apps`        | تطبيقات GitHub التي يثق بها فلو: `gate.login` (و`gate.aliases` أثناء إعادة التسمية)، و`review.slug`، و`owner` الذي تُحتسب موافقته. لا افتراضيات؛ وبلا تطبيق بوابة يرفض `land`          |

## أين يُتتبَّع العمل ويُشغَّل

| المفتاح   | يختار                                                                                                                                                                                    |
| --------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tracker` | `linear` (مع `team` و`branchPrefix`) أو `github-issues` (مع `branchPrefix`). المفاتيح `<prefix>-<n>`؛ و`start` يصنع `<branchPrefix>/<key>-<slug>`. بدونه ترفض الأوامر التي تحرّك القضايا |
| `runner`  | أين تعمل فحوص `gate run`: `ssh` مع `host`، أو `local`، أو `command` مع قائمة وسائط (عندنا `testbed run …`)، أو `github-actions` مع سير عمله. بدون واحد يرفض `gate run`                   |
| `gate`    | `check`، أمر الفحص (افتراضيًا `pnpm verify`)، و`shard`، الفحص الذي تشغّله شظية واحدة مع `{filters}` لحزمها                                                                               |
| `specs`   | أين تسكن المواصفات: `dir` (افتراضيًا `.agents/specs`) و`bugsDir`                                                                                                                         |

## ما يصيّره sync

| المفتاح      | يختار                                                                                                                                               |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| `preset`     | `neutral` (الافتراضي)، أو `stackra`، أو حزمة npm مثل `@acme/flow-preset`، أو مسار إلى مجلد إعداد مسبق خاص بالمستودع ([الإعدادات المسبقة](/presets)) |
| `profile`    | أيّ وكلاء الإعداد المسبق ومهاراته وخطّافاته يصيّرها `sync`، من الملفات الشخصية التي يعلنها `preset.yml` فيه؛ يسجّله `.flow/lock.json`               |
| `harnesses`  | أدوات البرمجة التي يصيّر لها `sync --direct` أوامر `flow-*` ([أدوات البرمجة](/coding-tools))                                                        |
| `claudeCode` | ملحقات Claude Code الخاصة بالمستودع، `enabledPlugins` و`extraKnownMarketplaces`، مدمجةً فوق ملحقات الإعداد المسبق؛ السوق المحلية مرفوضة             |
| `agentsMd`   | `facts`، نص Markdown الخاص بالمستودع تحت «This repository» في `AGENTS.md`؛ و`land`، الذي يستبدل سطر الهبوط                                          |
| `session`    | `pushAtEnd` (افتراضيًا `false`): يصيّر الخطّافات التي تكتب سجل الجلسة وتدفع عملها حين تنتهي؛ و`contextCommands`، أوامرُ يُلحق بدء الجلسة مخرجاتها   |

## الهبوط والإصدار

| المفتاح     | يختار                                                                                                                                                                              |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `approve`   | أنماط `ownerOnly` إلى جانب قائمة فلو، و`checks` (تسجيل الدخول الموثوق لسياق مطلوب)، و`workflows` التي توقظ مسار الهبوط على main، و`requesters` الذين تُحتسب شارة `fflow:land` منهم |
| `review`    | `required`، فئات المواصفة التي تنال تغييراتها مراجعة الذكاء الاصطناعي (افتراضيًا `small` و`feature` و`big`)؛ المراجعة استشارية                                                     |
| `train`     | قطار الإصدار: `label`، و`eject` (`bisect` أو `manual`)، و`after` (المستودعات الأعلى)، و`cutoff` بالساعات ([الإصدارات والقطارات](/release-trains))                                  |
| `artifacts` | الحارس الذي يطبّقه `gate run` و`land` على التغيير: `paths` (افتراضيًا ذاكرات التخزين ومخرجات البناء) و`maxBytes` (افتراضيًا 5 ميغابايت)                                            |
| `clean`     | `keep`، أنماط أشجار عمل لا تُزال أبدًا؛ و`whenMerged`، تنظيفٌ في الخلفية عند بدء الجلسة؛ و`budget`، أكثر ما يُحتفظ به من أشجار العمل (افتراضيًا 10)                                |

## التجاوزات

يغيّر المستودع ما يصيّره `sync` دون تفريع إعداد مسبق: ملفات يملكها المالك وحده في
`.flow/overrides/<surface>/<id>.yml`، لكلٍّ منها `kind: disable | extend | configure | replace` مع `target`، وللنوعين
`replace` و`disable` سببٌ `reason` ومالكٌ `owner` وموعد مراجعة `review` (يحذّر `fflow check` قبله بأربعة عشر يومًا
ويفشل بعده). السياسات الإلزامية (`guard.secrets` و`guard.tenancy` و`owner-only` و`guard.wiring`) لا تُعطَّل ولا
تُستبدل ولا تُضبط؛ و`extend` لإحداها لا يجوز له إلا الإضافة. وترويسة الملف الذي شكّله تجاوزٌ تسمّيه.

## مجلد .flow والقفل

يكتب `fflow init` المجلد `.flow/`: ملف README ودستورًا مبدئيًا و`.gitignore`. ويكتب `fflow sync` الملف
`.flow/lock.json`، كلَّ ملف مصيَّر ببصمته وبصمة الإعداد المسبق؛ ويُفشل `fflow check` التكامل المستمر حين ينحرف ملف
أو يختلف الإعداد المسبق المثبّت عن القفل، ويعتمد `fflow update` إصدارًا جديدًا من الإعداد المسبق بعد طباعة الفرق.
و`.flow/readme.yml` هو البيانات التي يصيّر منها `fflow readme` الملف `README.md`.
