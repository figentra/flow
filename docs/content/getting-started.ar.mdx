يهيّئ هذا الدليل فلو في مستودع GitHub بالإعداد المسبق `neutral` وGitHub Issues متتبِّعًا. ويأخذ أول تغيير من المواصفة
إلى المهام. تحتاج البوابة والهبوط إلى تهيئة تطبيق GitHub مرةً واحدة، وهي في آخر الدليل.

## قبل أن تبدأ

- Node.js 24 أو أحدث، وgit.
- مستودع GitHub يمكنك الدفع إليه.
- pnpm أو npm أو yarn. الأمثلة تستعمل pnpm.
- أداة برمجة تصيّر فلو أوامر لها: Claude Code أو OpenCode أو Codex أو GitHub Copilot أو Cursor.

## 1. التثبيت

تُنشر فلو في سجل فيجنترا، الذي يقرؤه أي أحد بلا رمز. عيّن نطاقيه في `.npmrc`:

```ini
@figentra-oss:registry=https://npm.stackra.figentra.com/
@stackra:registry=https://npm.stackra.figentra.com/
```

ثم أضف فلو تبعيةَ تطوير:

```sh
pnpm add -D @figentra-oss/flow
```

## 2. تهيئة المستودع

```sh
pnpm exec fflow init
```

يكتب `init`:

- `.flow/`، ومعه README ودستور مبدئي `constitution.md` و`.gitignore`؛
- ملف `flow.config.json` مبدئيًا لا يحمل إلا المخطط والإصدار، فتنطبق كل الافتراضيات؛
- أوامر `flow-*`، مصيَّرةً من الإعداد المسبق `neutral`.

يحمل الدستور القواعد التي تُفحص عليها مواصفاتك وخططك. استبدل بالنص المبدئي قواعد فريقك قبل أول مواصفة.

## 3. الضبط

يسمّي `flow.config.json` المحوّلات. لا شيء يتخلّف إلى اختيار مؤسسة ما: الأمر الذي يحتاج إعدادًا لم تضبطه يرفض ويسمّيه.
نقطة بداية لفريق يستضيف على GitHub:

```json
{
  "$schema": "./node_modules/@figentra-oss/flow/schema/flow.config.schema.json",
  "version": 1,
  "preset": "neutral",
  "harnesses": ["claude-code"],
  "credentials": { "kind": "gh-user" },
  "tracker": { "kind": "github-issues", "branchPrefix": "work" },
  "gate": { "check": "pnpm test" }
}
```

- `harnesses` يسرد أدوات البرمجة التي تُصيَّر الأوامر لها. أضف `"opencode"` أو `"codex"` أو `"copilot"` أو
  `"cursor"` بحسب حاجتك.
- `credentials` يقول كيف تنادي فلو GitHub. يستعمل `gh-user` تسجيل دخولك في `gh`، عن قصد. ويقرأ `env` الرمز
  `GH_TOKEN` من البيئة، ويشغّل `wrapper` أمرك أنت الذي يسلّم `gh` رمزَ روبوت.
- `tracker` مع `github-issues` يجعل القضية `#12` المفتاح `gh-12`. ويعمل Linear (‏`team`، `branchPrefix`) وJira
  (‏`site`، `project`، `branchPrefix`) بالطريقة نفسها.
- `gate.check` هو الأمر الذي تشغّله البوابة. الافتراضي `pnpm verify`.

ثم صيّر الإعداد وافحصه:

```sh
pnpm exec fflow sync --direct   # يصيّر الأوامر والوكلاء والقواعد والخطّافات وأسطر العمل
pnpm exec fflow doctor          # Node وgit والإعداد والإعداد المسبق وبيانات الاعتماد، ولكلٍّ إصلاحه
```

التزم بكل ما كتبه `sync`، ومنه `.flow/lock.json`. وأضف `fflow check` إلى التكامل المستمر: يفشل حين يُعدَّل ملف مصيَّر
يدويًا، أو يتغيّر الإعداد المسبق بلا `fflow update`، أو يخالف الإعداد مخططه.

## 4. خذ أول تغيير حتى النهاية

افتح قضية للتغيير، ثم ابدأ شجرة عمله:

```sh
pnpm exec fflow start gh-12
```

يصنع `start` الفرع `work/gh-12-<slug>` وشجرة العمل `.claude/worktrees/gh-12-<slug>`، ويضيف `spec.md` من قالب
المواصفة في `.agents/specs/gh-12-<slug>/`. وفي شجرة العمل اطلب من أداة البرمجة:

1. `/flow-specify` يكتب المواصفة من طلبك: المتطلبات ومعايير القبول و**الفئة**.
2. `/flow-clarify` يسأل الأسئلة المفتوحة، في واجهة أسئلة الأداة حيث تملك واحدة، ويسجّل كل إجابة في المواصفة.
3. `/flow-plan` يكتب الخطة والمهام. تتوقف مواصفة `feature` أو `big` هنا لمن يوافق عليها أولًا (انظر
   [الموافقات](/approvals)).
4. `/flow-build` يبني المهام موجةً موجة، ومهام الموجة بالتوازي، ويتوقف عند موجة فاشلة. ولا تُؤشَّر المهمة إلا حين يرى
   `fflow task done` فحصها يمرّ عند رأس نظيف.

في أي لحظة يقول `fflow next` مرحلة المواصفة والأمر الذي يحرّكها. ويقول `fflow gate check <folder>` ما تحتاجه الحالة
التالية بعد، مع السطر الذي يُصلَح.

العمل التافه لا يحتاج مواصفة: `fflow start gh-13 --no-spec`.

## 5. البوابة والهبوط

ادفع الفرع وافتح طلب الدمج. يحتاج أمران آخران إلى تهيئة مرة واحدة، على يد مالك المستودع:

- **تطبيق بوابة.** يُنشر `fflow/gate` بوصفه تطبيق GitHub تملكه، لا برمز شخصي أبدًا. ينشئ `fflow app create gate`
  واحدًا من الطرفية ويطبع `apps.gate.login` الذي يُضبط.
- **مشغِّل.** أين تعمل الفحوص: `"runner": { "kind": "github-actions" }` يشغّلها في سير عمل طلب الدمج نفسه (يكتبه
  `fflow init --runner github-actions`). و`local` و`ssh` و`command` تشغّلها في مكان آخر.

تغطي [البوابات](/gates) التهيئة وما تفحصه البوابة. ومتى صارت في مكانها:

```sh
pnpm exec fflow gate run   # شغّل الفحوص عند الرأس المدفوع؛ يُوضع fflow/gate على الالتزام
pnpm exec fflow land       # ادمج متى صار أخضر وموافَقًا عليه وخاليًا من تغييرات المالك وحده
```

يضع `land` القضية في «منجزة»، ويزيل شجرة العمل، ويحذف الفرع.
