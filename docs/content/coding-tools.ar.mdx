يسمّي أمر `flow-*` ما تحتاجه الخطوة، لا الأداة التي تنفّذها: خطوة السؤال في `flow-clarify` و`flow-specify` كتلةُ
`ask` (‏`<!-- flow:ask -->` … `<!-- /flow:ask -->`؛ و`todo` و`docs` و`subagent` محجوزة بالطريقة نفسها). يصيّر محوّلُ
الأداة كلَّ أمر حيث تقرؤه أداة واحدة ويملأ كل كتلة لتلك الأداة. اختر الأدوات في `flow.config.json` وشغّل
`fflow sync --direct`:

```json
{ "version": 1, "harnesses": ["claude-code", "copilot"] }
```

## الأدوات

| الأداة        | الملفات                                 | خطوة `ask`                                                                                                                          |
| ------------- | --------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `claude-code` | `.claude/skills/flow-<verb>/SKILL.md`   | أداة `AskUserQuestion`: من سؤال إلى أربعة، ومن خيارين إلى أربعة، والموصى به أولًا موسومًا بـ«(Recommended)»، والنص الحر ممكن دائمًا |
| `opencode`    | `.opencode/commands/flow-<verb>.md`     | أداته `question`، بالطريقة نفسها                                                                                                    |
| `copilot`     | `.github/prompts/flow-<verb>.prompt.md` | الجدول النصي                                                                                                                        |
| `cursor`      | `.cursor/commands/flow-<verb>.md`       | الجدول النصي                                                                                                                        |
| `codex`       | `.agents/skills/flow-<verb>/SKILL.md`   | الجدول النصي                                                                                                                        |

حيث لا تتوافر أداة سؤال في الأداة، يحمل الأمر الجدول النصي ليُسأل به. لكل ملف مصيَّر ترويسةُ المصدر وبصمته في
`.flow/lock.json`، والأداة التي تُزال من القائمة تأخذ معها أوامرها غير المعدَّلة. بدون `harnesses` يصيّر `--direct`
ملفات Claude Code وOpenCode، ويصيّر `sync` المجرّد وثائق `.agents/skills/` المحايدة، وكلاهما بالجدول النصي. تُسجَّل
الإجابات في المواصفة، لا في محادثة الأداة وحدها؛ و`fflow_clarification_record` في خادم MCP يكتبها بالطريقة نفسها من
أي أداة.

## أوامر flow-\*

تتبع الأوامر مسار التغيير: `flow-specify` و`flow-clarify` يكتبان المواصفة ويحسمانها، و`flow-plan` الخطة،
و`flow-tasks` المهام، و`flow-implement` البناء، و`flow-analyze` فحص الاتساق، و`flow-checklist` قائمة المراجعة،
و`flow-converge` الإغلاق. يقرأ كلٌّ منها مدخلاته عبر `fflow spec …` ويسجّل عبر `fflow task …`، فيكون السجل، لا
المحادثة، هو حقيقة ما بلغه التغيير.

## خطّاف الحارس

`fflow guard` هو الخطّاف الذي تستدعيه الأداة عند حدث (أمرُ صدفة على وشك التشغيل، ملفٌ على وشك الكتابة): يطبّق قواعد
الإعداد المسبق والأبواب الجانبية والملفات السرية، ويرفض مع السبب. ويطبع `fflow guard --print-settings` الخطّافات
التي توصل `.agents/hooks/fflow-guard.mjs` بأربعة أحداث. يُصيَّر الحارس دائمًا أيًّا كان الملف الشخصي؛ والسياسات
الإلزامية وراءه (`guard.secrets` و`guard.tenancy` و`owner-only` و`guard.wiring`) لا تُطفأ ([الإعداد](/configuration)).

## Codex

يستعمل Codex الأداة `codex` الموجودة و`AGENTS.md` و`.agents/skills/`؛ ولا يضيف فلو محوّل Codex ثانيًا ولا ملفات
مطالبات في المجلد الرئيسي. يصيّر `fflow sync` المجرّد مهاراتٍ أصلية. وللإعداد المختلط أدرج `"codex"` في `harnesses`
واستعمل `fflow sync --direct`؛ وراجع `fflow diff` قبل تحديث إعداد قائم محكوم. افتح Codex في المستودع واستدعِ مهارة
مصيَّرة مثل `$flow-plan`. خطّافات فلو الخاصة بـClaude و`.mcp.yaml` ليست دليلًا على أن Codex يفرض الخطّافات أو يسجّل
MCP: سجّل `fflow mcp` في إعداد MCP الخاص بالعميل عند الحاجة؛ ويعمل بحث السياق من سطر الأوامر بلا MCP
([سياق المهمة](/context)).
