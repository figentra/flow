يعمل `fflow` على `@stackra/console`، محرّك سطر الأوامر الواحد لكل أدوات فيجنترا. يطبع `fflow` وحده الشعار والإصدار
والأوامر بحسب المجموعة؛ ويطبع `fflow <command> --help` استخدام الأمر ولا يشغّل شيئًا؛ وأمرٌ مكتوب خطأً يسمّي
الأقرب إليه ويخرج بالرمز 2. الفشل كتلةُ خطأ واحدة: ما فشل، ولماذا، والإصلاح، ورابط إلى الوثائق. المخرجات نصٌّ
خام تحت `NO_COLOR` أو داخل أنبوب، والأوامر التي تقبل `--json` تكتب مستندًا واحدًا، `{ "ok", "data" }`. يرفض الأمر
رايةً لم يعلنها، بالرمز 2، بدل أن يتجاهلها.

الجدول الكامل، بكل راية ورمز خروج، هو
[قسم الأوامر في README](https://github.com/figentra/flow/blob/main/packages/flow/README.md#commands)؛ وهذه الصفحة
تجمع الأوامر بحسب الغرض منها.

## تهيئة مستودع

| الأمر                                | ما يفعله                                                                                         |
| ------------------------------------ | ------------------------------------------------------------------------------------------------ |
| `fflow init [--force]`               | يكتب `.flow/`، وملف `flow.config.json` مبدئيًا إن لم يكن موجودًا، ويصيّر مهارات `flow-*`         |
| `fflow init --runner github-actions` | يكتب سير عمل البوابة للمستودعات التي لا صندوق لها                                                |
| `fflow migrate [--dry-run]`          | ينقل مستودعًا على spec-kit إلى `.flow/`، ثم يزامن                                                |
| `fflow preset add <pkg>`             | يثبّت حزمة إعداد مسبق ويضبط `"preset"` في `flow.config.json`؛ شغّل `fflow sync` بعده             |
| `fflow doctor [--json] [--offline]`  | يفحص Node وgit والإعداد والإعداد المسبق وتثبيت `.flow/` والقائمة وبيانات الاعتماد، ولكلٍّ إصلاحه |

## إبقاء الملفات المصيَّرة متوافقة

| الأمر                   | ما يفعله                                                                                                                                                                      |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `fflow sync [--direct]` | يصيّر مهارات `flow-*` والوكلاء والقواعد وأسطح الإعداد المسبق بترويساتها، ويكتب `.flow/lock.json`؛ يرفض إعدادًا مسبقًا يختلف عن القفل                                          |
| `fflow update`          | يطبع الفرق، ويعتمد الإعداد المسبق المثبّت في القفل، ثم يزامن                                                                                                                  |
| `fflow check`           | فحص التكامل المستمر: يفشل مسمّيًا كل سبب، على ملف انحرف أو إعداد مسبق غير معتمد أو إعداد أو تجاوز غير صالح أو سياسة إلزامية معطّلة أو تجاوز تجاوز موعد مراجعته؛ لا يكتب شيئًا |
| `fflow diff`            | يطبع كل ملف سيضيفه `sync` أو `update` أو يغيّره أو يحذفه؛ لا يكتب شيئًا                                                                                                       |
| `fflow validate`        | يفحص `flow.config.json` و`.flow/overrides/` على مخططاتها والسياسات الإلزامية                                                                                                  |
| `… --workspace <dir>`   | يشغّل `sync` أو `update` أو `check` أو `diff` أو `validate` في كل مستودع تحت `<dir>` فيه `flow.config.json`                                                                   |

## أخذ التغيير عبر مراحله

| الأمر                                                       | ما يفعله                                                                                                                                |
| ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `fflow start <KEY> [--slug s] [--no-spec]`                  | الفرع وشجرة العمل من الفرع الافتراضي، والقضية قيد التنفيذ، والسجل ملتزَمًا به ومدفوعًا؛ مفتاحٌ بلا مجلد مواصفة يأخذ `spec.md` من القالب |
| `fflow spec paths \| setup-plan \| setup-tasks \| template` | مجلد المواصفة ووثائقه والقوالب المحلولة، لأوامر `flow-*`                                                                                |
| `fflow spec ask <key> [--async]`، `fflow spec resume <key>` | أسئلة المواصفة المفتوحة؛ `--async` ينشرها على القضية، و`resume` يسجّل الإجابات المعطاة هناك                                             |
| `fflow gate plan <spec.md>`                                 | يخرج بالرمز 1 حتى يجوز التخطيط للمواصفة                                                                                                 |
| `fflow plan <key> --input \| --record <tasks.md>`           | مدخلات سير عمل التخطيط، ومهامه تُكتب فقط حين تُغطّى كل المتطلبات والمعايير                                                              |
| `fflow task start \| done <key> <T###>`                     | يحرّك علامة المهمة؛ `done` يؤشّرها فقط حين يخرج فحصها بالرمز 0 عند رأس نظيف                                                             |
| `fflow task wave <key>`                                     | يصفّ الموجة التالية من البناء ويطبعها                                                                                                   |
| `fflow next [<key>]`، `fflow resume <key>`                  | المرحلة التي بلغتها المهمة والأمر الذي يحرّكها؛ والعودة إلى مرحلة تركتها جلسة متوقفة نصف منجزة                                          |
| `fflow review <pr> --input \| --record`                     | مدخلات سير عمل المراجعة، ونتائجها المتحقَّق منها مسجَّلة؛ يرفض `land` نتيجةً مانعة مؤكَّدة                                              |
| `fflow gate run [--ref b] [--box host] [--shards n]`        | فحوص المستودع عبر المشغّل المضبوط عند الرأس المدفوع؛ يُنشر `fflow/gate` واحد                                                            |
| `fflow land [<pr>] [--dry-run]`                             | يدمج بالسحق طلب دمج أخضر على `fflow/gate` ومعه موافقاته، أو يطلب من مسار الهبوط على main                                                |
| `fflow clean [--merged] [--budget]`                         | يزيل أشجار العمل المنتهية، ويذكر ما أبقاه والمساحة المحرَّرة                                                                            |

## الإصدار

| الأمر                                                          | ما يفعله                                                                                |
| -------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `fflow release [--json] [--offline] [--preflight]`             | ما سينشره الإصدار التالي؛ `--preflight` يقول إن كان يجوز دمج طلب الإصدار الآن           |
| `fflow train <open\|add\|close\|build\|eject\|depart\|status>` | قطار الإصدار، للمستودعات التي لا طابور دمج لها ([الإصدارات والقطارات](/release-trains)) |
| `fflow ship <dev\|staging>`                                    | يطلق نشر Runway للمنتج على main؛ الإنتاج مرفوض، والمالك هو من يرقّي                     |
| `fflow adr reserve <slug> --issue <key>`                       | يُنزل رقم ADR التالي على الفرع الافتراضي تحت قفل طابور `adr`، ثم يطبعه                  |

## القراءة والإخبار

| الأمر                                    | ما يفعله                                                                                                          |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `fflow status [--json] [--offline]`      | المواصفات بحسب الحالة، وأشجار العمل، وطلبات الدمج المفتوحة ببوابتها ومراجعتها، والجلسات، لمساحة العمل             |
| `fflow trace trace <dir> \| drift \| ci` | مصفوفة المتطلب → المهمة → اختبار `@covers`، والانحراف بين المواصفة والفرق، وقواعد الإنجاز                         |
| `fflow parse <file>`                     | ما تقرؤه المحلّلات من `spec.md` أو `plan.md` أو `tasks.md` أو `routing.yaml`، بصيغة JSON                          |
| `fflow linear issue \| tasks`            | قضية Linear للمواصفة وقضية فرعية لكل مهمة؛ `--dry-run` لا يحتاج رمزًا                                             |
| `fflow context [--path] [--query]`       | تنقّل محدود دون اتصال في المستودع ([سياق المهمة](/context))                                                       |
| `fflow mcp`                              | خادم MCP على stdio: الحالة والمواصفة والتتبّع وأشجار العمل والمقاييس والأسئلة المفتوحة وبحث في الوثائق وكاتب واحد |
| `fflow readme [--check]`                 | يصيّر `README.md` من `.flow/readme.yml`؛ `--check` يخرج بالرمز 1 حين يختلفان                                      |
| `fflow guard`                            | محرّك الحارس على حدث خطّاف: قواعد الإعداد المسبق والأبواب الجانبية والملفات السرية                                |
| `fflow hooks run <stage>`                | مهام lefthook للمرحلة، هنا أو على صندوق المشغّل                                                                   |
| `fflow session stop [--save-only]`       | خطّاف SessionEnd: يلتزم بالعمل المتتبَّع مع السجل ويدفعه                                                          |

`fflow train` و`fflow team` و`fflow hooks` مجرّدةً أوامرُ مجهولة تخرج بالرمز 2. يقرأ `fflow linear` رمزه من البيئة
فقط (`LINEAR_AGENT_TOKEN`، وإلا `LINEAR_API_KEY`) ولا يطبعه أبدًا.
