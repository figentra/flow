فيجنترا فلو (`fflow`) هي أداة سطر الأوامر للمواصفات في التطوير الموجَّه بالمواصفة، للفرق التي تكتب المواصفة قبل
الشيفرة ولوكلاء البرمجة الذين يعملون إلى جانبها. يبدأ التغيير مواصفةً، ويتوقف لموافقة شخص، ويصير خطةً ومهامًا،
ويجتاز بوابةً، ويهبط طلبَ دمج مراجَعًا. تُبقي فلو المواصفة والخطة والمهام والاختبارات متوافقة مع تقدّم العمل، وترفض
خطوةً تسبق عملها، مع السبب والإصلاح.

تفحص فلو التوافق وتحرس ما يجوز له الهبوط. ولا تدّعي أبدًا أن الشيفرة صحيحة.

## مسار التغيير

| الخطوة   | ما يحدث                                                                             | أين                                   |
| -------- | ----------------------------------------------------------------------------------- | ------------------------------------- |
| المواصفة | يكتب الوكيل `spec.md` من الطلب ويسأل الأسئلة المفتوحة.                              | `/flow-specify`، `/flow-clarify`      |
| الموافقة | تتوقف مواصفة `feature` أو `big` لمن يوافق عليها قبل التخطيط أو قبل المهام.          | [الموافقات](/approvals)               |
| الخطة    | الخطة ومهامها بحجم طلب الدمج، كلٌّ منها تغطي متطلبات مسمّاة.                        | `/flow-plan`، `fflow plan`            |
| البناء   | تُؤشَّر كل مهمة فقط حين يمرّ فحصها عند رأس نظيف.                                    | `fflow task start`، `fflow task done` |
| البوابة  | تعمل فحوص المستودع عند الرأس المدفوع، ويُنشر `fflow/gate` على الالتزام.             | `fflow gate run`، [البوابات](/gates)  |
| الهبوط   | لا يُدمج طلب الدمج إلا حين يكون أخضر وموافَقًا عليه وخاليًا من تغييرات المالك وحده. | `fflow land`                          |
| الإصدار  | مجموعات التغيير، وطلب دمج الإصدار، وقطارات الإصدار حيث يلزم.                        | `fflow release`، `fflow train`        |

تمرّ كل مواصفة بست حالات بالترتيب: **مسوَّدة ← موضَّحة ← مخطَّطة ← مُمهَّمة ← قيد التنفيذ ← منجزة**. قد تتأخر الحالة عن
عملها، ولا تسبقه أبدًا.

## ما تصيّره فلو

يصيّر `fflow sync` إعداد الوكلاء في المستودع من [إعداد مسبق](/presets): أوامر `flow-*` لكل أداة برمجة، والوكلاء
والقواعد والمهارات، وخطّاف الحارس، وخطّافات git، وأسطر عمل التكامل المستمر. ويسجّل كل ملف ببصمته في
`.flow/lock.json`، ويُفشل `fflow check` التكامل المستمر حين ينحرف أحدها.

الأدوات محوّلات، تُختار لكل مستودع في `flow.config.json`:

- **المتتبِّع:** Linear أو GitHub Issues أو Jira.
- **المشغِّل:** GitHub Actions، أو جهازك، أو صندوق عبر SSH، أو أمرك أنت.
- **أدوات البرمجة:** Claude Code وOpenCode وCodex وGitHub Copilot وCursor.
- **بيانات الاعتماد والأسرار:** تسمّيها أنت. لا تتراجع فلو أبدًا إلى تسجيل دخول شخصي ولا تطبع سرًّا أبدًا.
